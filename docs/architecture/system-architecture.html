SYSTEM ARCHITECTURE

퀀트 운용 프로젝트 기본 구조

KIS Open API 연동은 open-trading-api를 기준으로 삼고, 목표 비중 리밸런싱과 안전 점검은 자체 구현하는 구조

open-trading-api는 인증, 잔고, 주문, 체결, 정정·취소의 API 규격 기준으로 사용한다. 목표 비중 기반 수량 계산, 주문 계획 ID, 사전 점검, SQLite 기록, 사후 대조는 프로젝트에서 구현한다. 연구(백테스트)와 운용(리밸런싱)은 따로 실행하고, 운용은 settings.yaml에 확정된 전략과 체결 정책만 따른다. 정해진 시각의 실행은 cron 대신 systemd timer가 맡고, 서비스의 ExecCondition이 휴장일 파일과 주문 가능 시간대를 확인한 뒤에만 실행한다. 주문 서비스의 timer에는 놓친 실행을 나중에 보충하는 Persistent 설정을 쓰지 않는다.
