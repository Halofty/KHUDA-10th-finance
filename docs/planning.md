# 구현 계획

세미나 발표(전략팀 공유)의 일정과 현재 저장소 구조(`README.md`, `docs/architecture/architecture.md`)를 맞춘 구현 계획이다.
진행하면서 바뀐 결정과 결과는 `docs/progress.md`에 남긴다.

## 목표와 일정

- **12/4(금)**: 검증 완료. 전략 버전을 고정하고 예행연습 결과로 실전 여부를 결정한다.
- **12/7(월)~12/24(목)**: 실전 운용 14거래일. 리밸런싱은 12/7·12/14·12/21 월요일에 3회 한다.
- 12/25는 휴장이다. 최종 대조는 12/24 장 마감 기준으로 한다.

## 원칙

1. **주문 한 건을 끝까지 먼저 완성한다.** 주문 계획 → 접수 → 체결 → 잔고 대조를 한 종목으로 KIS 모의 계좌에서 확인한 뒤 여러 종목으로 넓힌다. 흐름 확인용 가짜 계좌(PaperBroker)는 두지 않고 처음부터 모의 계좌로 확인한다. 서버 배포는 그다음에 한다.
2. **전략팀과 개발팀이 병렬로 작업한다.** 개발팀은 예시 목표 비중 표로 주문 경로를 만들고, 2주차에 전략팀의 실제 표를 연결한다.
3. **입출력 형식을 먼저 고정한다.** 전략 출력 `as_of, execution_date, ticker, target_weight, strategy_version`과 시세 표준 스키마를 바꾸지 않는다.
4. **모듈마다 테스트를 하나씩 남긴다.** 실제 KIS 키로 실행하는 것은 직접 한다.

## 역할

KIS를 직접 호출하는 파일은 주문 담당, pandas로 끝나는 계산은 데이터 담당, 실행 순서와 안전장치는 운영 담당이 맡는다.

| 담당 | 맡을 파일 | 추정 작업량 |
| --- | --- | --- |
| 데이터 (홍정의) | `data/*`, `jobs/fetch_prices.py`, `execution/order_planner.py`, `execution/reconcile.py`, `jobs/daily.py` | 약 7인·일 |
| 전략·백테스트 (박재현) | `strategy/*`, `backtest/*`, `jobs/backtest.py`, 전략팀 연결, 손계산 대조 | 약 7인·일 |
| 주문 (김상혁) | `kis/vendor/`, `kis/client.py`, `kis/kis_broker.py`, `execution/fill_tracker.py` | 약 7.5인·일 |
| 운영 (김경범) | `market_day.py`, `store/*`, `reporting/notifier.py`, `deploy/systemd/`, `execution/risk_gate.py`, `jobs/rebalance.py`(잠금·실행 순서) | 약 8인·일 |

- `order_planner`, `reconcile`, `jobs/daily`는 표와 표를 비교해 차이를 계산하는 pandas 작업이라 KIS를 몰라도 되므로 데이터 담당이 맡는다.
- `risk_gate`와 `jobs/rebalance`는 잠금, 재시작 복원, 건너뜀 기록이 SQLite·systemd와 바로 연결되므로 운영 담당이 맡는다.
- 장애 테스트(응답 유실, 부분 체결, 재시작)는 주문 담당과 운영 담당이 함께 한다.

### 검토 짝

검토가 곧 인수인계가 되도록, 서로 이어지는 담당끼리 짝을 지었다.

| 작성 | PR 검토 | 이유 |
| --- | --- | --- |
| 데이터 | 전략·백테스트 | 시세 형식을 직접 쓰는 쪽 |
| 전략·백테스트 | 데이터 | 목표 비중이 `order_planner`의 입력 |
| 주문 | 운영 | 시험 기간에 운영이 KIS 흐름을 대신 맡음 |
| 운영 | 주문 | 사전 점검과 systemd가 주문 흐름을 감싸고 있음 |

### 작업 규칙 (AI 도구를 쓸 때 포함)

1. 지금 구현하는 내용만 건드린다. AI로 수정했다면 `git diff`를 반드시 확인한 뒤 push한다.
2. 설명할 수 있는 코드만 올린다. 파일 맨 위 주석에 무엇을 하는 코드인지, 어떤 구조인지 직접 설명한다.
3. 브랜치 → PR → 승인 → 머지 순서로 작업한다.
